MCP server

Tools

What an assistant can call: tools that read people’s trips, and tools that change their stops. Each returns JSON, as structured content and as text.

An example call

Adding a hotel for two nights. The assistant’s MCP client sends this for it, with the access token from sign-in:

POST /api/mcp
Authorization: Bearer <access token>
Content-Type: application/json

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "add_stop",
    "arguments": {
      "trip_id": "k3v9qz7p2m4x",
      "name": "Zion Lodge",
      "lat": 37.2506,
      "lng": -112.9571,
      "time": "2026-05-14T16:00",
      "kind": "hotel",
      "nights": 2
    }
  }
}

The stop comes back as saved, with its new id:

{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "structuredContent": {
      "stop": {
        "id": "3f9a1c0b7e2d4a65",
        "name": "Zion Lodge",
        "address": "",
        "lat": 37.2506,
        "lng": -112.9571,
        "time": "2026-05-14T16:00",
        "tz": null,
        "duration": null,
        "checkout": null,
        "kind": "hotel",
        "nights": 2,
        "travel": "drive",
        "back": {},
        "note": "",
        "links": [],
        "updatedBy": "Sam",
        "updatedAt": "2026-11-10T18:22:05.000Z"
      }
    },
    "content": [{ "type": "text", "text": "{\"stop\":{\"id\":\"3f9a1c0b7e2d4a65\", …}}" }]
  }
}

A wrong argument comes back as a result too, with isError, saying which one and what it should be, so the assistant can try again:

{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [{ "type": "text", "text": "time isn’t valid: When you arrive, \"YYYY-MM-DDTHH:MM\", in the clock time where the stop is …" }],
    "isError": true
  }
}
