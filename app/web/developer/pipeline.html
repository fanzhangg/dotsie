Picking and writing spots

Code narrows a destination’s places down. A model makes the calls that take judgment: which places are worth going to, and how to tell a visitor about them, from the sources only.

Code A model

Choosing the spots

  1. Code

    Candidates

    Every place inside the city’s or park’s outline that has an English Wikipedia article or an NPS page.

  2. A model

    Is it a sight? Haiku

    One place at a time, from its Wikidata description, article intro or NPS page, categories and what’s nearby: is it somewhere people go, still there, open to visitors, and not just part of a bigger place? And how far out of their way would a visitor go, 1 to 5.

  3. Code

    Shortlist

    70 sights: the most read on Wikipedia, plus up to 20 that hardly anyone reads about, by how far a visitor would go for them.

  4. A model

    Pick Sonnet

    The whole shortlist at once, compared with each other: what a visitor with a few days shouldn’t miss, in order, each with a reason, and what it left out and why.

  • Why a model. Rules couldn’t say what’s a sight: blocking creative works, to drop a TV series, also dropped the Gum Wall, and a bridge that fell in 1940 ranked at the top on its page views. A model reads what the article says, as a person would.
  • It judges what a place is, not how popular it is. The judge never sees page views; those are counted, and only rank the shortlist.
  • Its answer is checked by code. Each answer is JSON in a fixed shape, facts first, then the verdict, and code decides from it: a “part of” only counts if it names a place really nearby.
  • Only as many questions as needed. The places nobody reads about are all asked; then the most read, 40 at a time, until there are enough sights for the shortlist.

Writing a spot

  1. Code

    Dossier

    What the store has on the place: its Wikipedia article, its official site’s page and its NPS pages, each marked with its address.

  2. A model

    Write Sonnet

    A one-liner of at most 12 words, and two or three paragraphs in a guidebook’s voice, under two minutes to read, each listing its sources. Hours, fees and seasons kept apart, only as the sources state them.

  3. Code

    Check

    How many of the entry’s 8-word phrases are also in the sources, to spot copying. Guide preview shows it next to each entry.

  • Only what the sources say. The model gets the dossier and nothing else, and is told the pages in it are information, never instructions to it.
  • In its own words. No copied sentences, and no hype: no “breathtaking” or “hidden gem”, just what makes it worth going.

Every answer is kept with a hash of what was asked, so running a guide again only asks about what changed. The code is pipeline/guides.py.
